# Telegram-бот для скачивания видео и аудио

Готовый проект на **Node.js 24+** и **node-telegram-bot-api 2.1.0**. Пользователь подписывается на каналы, выбирает MP4 или MP3, отправляет ссылку и получает файл. Скачивание выполняет `yt-dlp`, обработку — FFmpeg. Работает в личных сообщениях с ботом, через long polling.

На старте установлены ограничения: **49 МБ на готовый файл, 20 минут на ролик, видео до 720p, MP3 192 кбит/с, одна задача одновременно и 20 мест в очереди**. Видео подбирается в H.264/AAC и переупаковывается в MP4; аудио преобразуется в MP3. Разрешение видео может автоматически снизиться, чтобы файл поместился. Массовое перекодирование видео на слабом сервере не выполняется.

Библиотека Telegram закреплена на ветке **2.x**. У неё именованные экспорты `Bot`/`Api` и методы с объектом параметров. Примеры со старым `new TelegramBot(token, { polling: true })` относятся к прежней несовместимой ветке. У текущей версии нет прежней цепочки зависимостей `request`.

## 1. Что установить

| Компонент | Назначение | Windows 11 | Linux |
| --- | --- | --- | --- |
| Node.js 24 LTS или новее | Сам бот и JavaScript runtime для YouTube | Установщик с [nodejs.org](https://nodejs.org/en/download) | Node.js 24, путь для systemd обычно `/usr/bin/node` |
| yt-dlp, актуальная версия | Получение метаданных и медиа | Официальный `yt-dlp.exe` | Python virtualenv + `yt-dlp[default]` |
| FFmpeg + ffprobe | MP4, MP3 и проверка результата | Windows-сборка FFmpeg с обоими exe | Пакет `ffmpeg` |

На Windows Python отдельно **не нужен**, если использовать официальный `yt-dlp.exe`. На Linux потребуется Python 3.10+ и `python3-venv`. Redis, база данных, Docker, Nginx, домен и входящий HTTPS-порт для этого варианта не нужны. Серверу нужен исходящий доступ к Telegram, YouTube и его CDN.

Используйте материалы, на скачивание которых у вас есть права или разрешение. Бот не обходит приватность, платный доступ, возрастные и региональные ограничения. Доступность публичного ролика также зависит от IP сервера и текущих ограничений YouTube.

## 2. Создать бота и настроить каналы

1. Откройте официальный [@BotFather](https://t.me/BotFather), выполните `/newbot` и сохраните токен.
2. Добавьте созданного бота **администратором каждого обязательного канала**. Проверка чужой подписки через `getChatMember` гарантируется Telegram, когда бот является администратором. Право публикации сообщений для сценария не требуется.
3. Скопируйте `.env.example` в `.env`, а `config/channels.example.json` — в `config/channels.json`.
4. В `.env` замените `BOT_TOKEN` на свой токен. Не публикуйте этот файл, не включайте его в архивы и не отправляйте токен в переписке.
5. В `config/channels.json` укажите свои каналы:

```json
[
  {
    "id": "@public_channel",
    "title": "Новости проекта",
    "url": "https://t.me/public_channel"
  },
  {
    "id": "-1001234567890",
    "title": "Закрытый канал",
    "url": "https://t.me/+YOUR_INVITE_LINK"
  }
]
```

`id` нужен для проверки подписки, `url` — для кнопки перехода, `title` — подпись кнопки. Для приватного канала используйте реальный числовой ID и действующую ссылку приглашения. ID можно получить из обновления Bot API о сообщении этого канала (`channel_post.chat.id`); для публичного канала его также возвращает `getChat`. Числовой ID стабилен при смене username и подходит также для публичных каналов. Если в приватном канале включены заявки, пользователь получит доступ после одобрения заявки и фактического вступления.

Разрешено до 10 обязательных каналов. **Пустой массив `[]` явно отключает требование подписки.** Отсутствующий или некорректный файл не отключает проверку: бот откажется запускаться.

После первого запуска отправьте своему боту `/id`. Впишите полученный Telegram user ID в `.env`:

```dotenv
ADMIN_USER_IDS=123456789
```

Владельцев может быть несколько: `ADMIN_USER_IDS=123456789,987654321`. После изменения `.env` перезапустите бота. Оставленное пустым значение выключает команду управления каналами.

## 3. Запуск на Windows 11

Установите Node.js 24 LTS. После установки откройте **новое** окно PowerShell и проверьте:

```powershell
node --version
npm --version
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm` в командах ниже. Менять системную политику выполнения скриптов не требуется.

Скачайте официальный [yt-dlp.exe](https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp.exe) и положите, например, в `C:\Tools\yt-dlp\yt-dlp.exe`.

На [странице FFmpeg](https://ffmpeg.org/download.html#build-windows) выберите Windows-сборку, например [Gyan essentials](https://www.gyan.dev/ffmpeg/builds/). Распакуйте её так, чтобы были файлы:

```text
C:\Tools\ffmpeg\bin\ffmpeg.exe
C:\Tools\ffmpeg\bin\ffprobe.exe
```

Нужны обычные сборки с кодеками `libmp3lame` и `libx264`. Не устанавливайте вместо FFmpeg одноимённый npm- или pip-пакет: это не замена исполняемым файлам.

Распакуйте проект и перейдите в его корневую папку. Выполните:

```powershell
npm ci
Copy-Item .env.example .env
Copy-Item config/channels.example.json config/channels.json
```

Заполните токен, каналы и пути в `.env`. Для Windows удобно использовать прямые слеши:

```dotenv
YT_DLP_PATH=C:/Tools/yt-dlp/yt-dlp.exe
FFMPEG_PATH=C:/Tools/ffmpeg/bin/ffmpeg.exe
FFPROBE_PATH=C:/Tools/ffmpeg/bin/ffprobe.exe
```

Путь с пробелами можно заключить в кавычки средствами `.env`, например `FFMPEG_PATH="C:/Program Files/ffmpeg/bin/ffmpeg.exe"`. Не добавляйте аргументы команды в переменную пути. FFmpeg и ffprobe должны находиться в одном каталоге, чтобы yt-dlp смог объединять дорожки.

Проверьте окружение и запустите бота:

```powershell
npm run doctor
npm run doctor -- --telegram
npm test
npm run smoke
npm run setup:telegram
npm start
```

`doctor` проверяет версии программ, параметры и файл каналов. Флаг `--telegram` дополнительно проверяет токен, доступ к Telegram, права администратора во всех каналах и отсутствие webhook. `smoke` создаёт секундный синтетический ролик и проверяет реальное создание MP4/MP3; YouTube и токен для него не нужны. `setup:telegram` однократно настраивает меню команд.

Остановка — `Ctrl+C`. Для разработки есть `npm run dev`, использующий встроенный `node --watch`; при изменении исходников он перезапускает процесс. Временные папки находятся вне `src`.

## 4. Постоянная работа на Linux без Docker

Пример ниже рассчитан на Ubuntu 24.04/Debian с systemd. Разумная отправная точка — **2 vCPU, 2 ГБ RAM и SSD от 20 ГБ** при одной одновременной задаче. Это стартовая рекомендация, а не обещание конкретного числа загрузок в минуту: скорость зависит от роликов, диска и канала связи.

Установите Node.js 24 по инструкции для вашей ОС на [nodejs.org](https://nodejs.org/en/download). Обычный `apt install nodejs` может поставить слишком старую версию. Например, если выбран репозиторий NodeSource, его официальный установочный скрипт можно сначала скачать и просмотреть:

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x -o /tmp/nodesource_setup.sh
less /tmp/nodesource_setup.sh
sudo bash /tmp/nodesource_setup.sh
sudo apt-get install -y nodejs
node --version
command -v node
```

Затем установите остальные программы и создайте отдельного системного пользователя:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg python3 python3-venv unzip ca-certificates
sudo useradd --system --create-home --home-dir /var/lib/mediabot --shell /usr/sbin/nologin mediabot
sudo install -d -o mediabot -g mediabot /opt/telegram-media-bot
```

Загрузите исходники из архива в `/opt/telegram-media-bot` так, чтобы там лежали `package.json`, `src`, `scripts` и остальные файлы проекта. **Не переносите Windows `node_modules`**; установите зависимости на сервере заново. Далее:

```bash
sudo chown -R mediabot:mediabot /opt/telegram-media-bot
cd /opt/telegram-media-bot
sudo -u mediabot npm ci --omit=dev
sudo -u mediabot python3 -m venv .venv
sudo -u mediabot .venv/bin/python -m pip install --upgrade 'yt-dlp[default]'
sudo -u mediabot cp .env.example .env
sudo -u mediabot cp config/channels.example.json config/channels.json
sudo -u mediabot mkdir -p data/tmp
sudo chmod 600 .env
```

Заполните `.env` и `config/channels.json` на сервере. В `.env` укажите:

```dotenv
YT_DLP_PATH=/opt/telegram-media-bot/.venv/bin/yt-dlp
FFMPEG_PATH=/usr/bin/ffmpeg
FFPROBE_PATH=/usr/bin/ffprobe
TEMP_DIR=/opt/telegram-media-bot/data/tmp
```

Пакет `yt-dlp[default]` включает необходимые компоненты EJS. Бот явно разрешает Node.js как JavaScript runtime для YouTube. Не устанавливайте старый системный yt-dlp вместо актуального пакета в virtualenv.

Проверьте запуск от того же пользователя, под которым будет работать служба:

```bash
sudo -u mediabot npm run doctor
sudo -u mediabot npm run doctor -- --telegram
sudo -u mediabot npm test
sudo -u mediabot npm run smoke
sudo -u mediabot npm run setup:telegram
```

В `deploy/telegram-media-bot.service` проверьте `ExecStart`: путь к Node должен совпадать с `command -v node`. Образец использует `/usr/bin/node`; Node из пользовательского nvm при `ProtectHome=true` службе недоступен. После этого установите службу:

```bash
sudo cp deploy/telegram-media-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-media-bot
sudo systemctl status telegram-media-bot
sudo journalctl -u telegram-media-bot -f
```

Управление службой:

```bash
sudo systemctl restart telegram-media-bot
sudo systemctl stop telegram-media-bot
```

Шаблон ограничивает процесс и его потомков: `MemoryMax=768M`, `CPUQuota=150%`, `TasksMax=96`. Настройте эти значения под сервер; при увеличении параллельности потребуется больше памяти и диска. Лимит V8 в 192 МБ относится к Node, а `MemoryMax` — ко всему дереву службы, включая Python/FFmpeg. При превышении жёсткого лимита задача может оборваться, а systemd перезапустит службу. Постоянный цикл ошибок ограничен `StartLimitBurst`.

Рабочая папка исходников для службы доступна на чтение, `data` — на запись. Эта папка должна существовать до запуска systemd. Не запускайте одновременно процесс на Windows и службу на Linux с **одним токеном**: Telegram не допускает двух независимых получателей polling.

## 5. Как добавлять и удалять каналы

1. Перед добавлением канала сделайте бота его администратором.
2. Отредактируйте `config/channels.json`. Предпочтительно сохранять готовый файл атомарно через замену; JSON не допускает комментариев и завершающих запятых.
3. Отправьте боту `/reload_channels` с аккаунта из `ADMIN_USER_IDS`.

Команда читает файл, проверяет весь список и права бота, после чего заменяет настройки одним действием. При ошибке остаётся предыдущий список. Номер версии списка входит в ключ кеша, поэтому успешная перезагрузка делает предыдущие подтверждения подписки недействительными.

Подписка проверяется при отправке ссылки, повторно при старте задачи из очереди и ещё раз перед отправкой файла. Если пользователь отписался или появился новый обязательный канал, доступ к результату будет закрыт. Короткий кеш используется для меню и выбора формата. При гонке между изменением списка и проверкой бот просит повторить запрос; сетевой сбой не открывает доступ.

Кнопки под уже отправленным приветствием не меняются автоматически. Новые кнопки пользователь получит через `/start`; старая кнопка «Проверить» всё равно проверяет текущий список. Изменение списка во время уже начавшейся отправки не может отозвать файл, принятый Telegram.

Перезапуск также перечитывает файл. Другие настройки `.env`, в том числе владельцы, применяются после перезапуска.

## 6. Архитектура и добавление платформ

```text
src/
  index.js                         # сборка зависимостей, запуск, остановка
  config/index.js                  # .env -> проверенная конфигурация
  bot/
    handlers.js                    # команды, кнопки, пользовательский сценарий
    keyboards.js                   # клавиатуры Telegram
    update-guard.js                # защита входящего потока
  core/
    errors.js                      # коды ошибок и безопасные ответы
    job-queue.js                   # очередь, конкуренция, отмена
    ttl-store.js                   # ограниченные по памяти TTL-хранилища
  platforms/
    registry.js                    # контракт платформы, маршрутизация ссылки
    youtube/
      provider.js                  # ссылки YouTube, метаданные, yt-dlp
      formats.js                   # выбор H.264/AAC с учётом размера
  services/
    channels.js                    # загрузка и атомарная смена каналов
    subscriptions.js               # getChatMember, проверка всех подписок
    download-job.js                # весь жизненный цикл одной задачи
    media-converter.js             # MP4/MP3, ffprobe, финальный размер
  infrastructure/
    telegram.js                    # API 2.x, потоковая отправка и повторы 429
    api-scheduler.js               # лимиты частоты вызовов Telegram
    process-runner.js              # spawn без shell, тайм-аут, остановка дерева
    temp-storage.js                # отдельные папки, свободное место, уборка
    dependencies.js                # проверка установленных программ
    logger.js                      # структурированные безопасные журналы
config/channels.example.json       # пример списка подписок
scripts/                           # диагностика, настройка, smoke-проверка
test/                              # автоматические тесты
deploy/telegram-media-bot.service   # Linux-служба без Docker
```

Обработчики знают о реестре платформ, а не об устройстве YouTube. Платформа не отправляет сообщения в Telegram и не создаёт собственную очередь. Её контракт описан в `src/platforms/registry.js`:

```js
class AnotherProvider {
  id = 'another-platform';

  supports(url) {
    // Проверяйте ТОЧНЫЙ список разрешённых доменов.
    return url.hostname === 'allowed.example';
  }

  normalize(url) {
    // Проверьте путь и ID, отбросьте лишние параметры.
    // Верните каноническую HTTPS-ссылку либо выбросьте AppError.
  }

  async download({ url, kind, directory, signal }) {
    // Получите исходник в directory, учитывая signal и лимиты config.
    // Верните { path, title, duration }.
  }
}
```

Это описание интерфейса, а не готовый загрузчик другой платформы. Для новой реализации:

1. Создайте `src/platforms/<name>/provider.js`.
2. Реализуйте контракт. Разрешайте конкретные домены и конкретные типы ссылок; не передавайте произвольный пользовательский URL в generic extractor.
3. Используйте общий `runProcess` для внешних программ и общий `AbortSignal`; сохраняйте исходник только в выданную папку. Учитывайте размеры, длительность и живые трансляции.
4. Для видео возвращайте MP4 с H.264/AAC либо расширьте `MediaConverter` осознанным режимом перекодирования и пересмотрите ресурсы. Аудио может быть исходного формата с аудиодорожкой — FFmpeg сделает MP3.
5. Зарегистрируйте экземпляр в `new PlatformRegistry([...])` в `src/index.js` и добавьте тесты нормализации/загрузки.
6. Обновите сообщения о поддерживаемых платформах в `/help` и `core/errors.js`.

Очередь, подписки, отмена, отправка и уборка останутся общими. Нет необходимости менять Telegram-обработчики для каждого нового источника.

## 7. Защита от нагрузки и ошибок

| Механизм | Что ограничивает |
| --- | --- |
| `DOWNLOAD_CONCURRENCY=1` | Только одна тяжёлая задача; слот удерживается до отправки и очистки |
| `MAX_QUEUE_SIZE=20` | Конечная очередь; лишние задачи получают ответ о перегрузке |
| Одна задача пользователя | Повторная ссылка не создаёт дубль |
| Пауза 15 секунд | Частоту принятых запросов на скачивание от одного пользователя |
| Входной guard | До 32 одновременно обрабатываемых событий и 8 событий за 10 секунд на пользователя |
| Ограниченные TTL-хранилища | До 10 000 записей в каждом кеше/хранилище |
| Планировщик API | До ~18 вызовов/сек, интервал отправок одному чату, конечный буфер и максимум 8 активных API-вызовов |
| Ограниченные повторы | Повторяются явные 429 с `retry_after`; неоднозначная ошибка отправки не повторяется |
| Длительность и тайм-ауты | Эфиры/слишком длинные ролики не принимаются; зависшие процессы останавливаются |
| Контроль диска | Проверка свободного места, лимит исходников, проверка размера папки каждые 500 мс |
| Проверка результата | ffprobe проверяет дорожки/кодеки/длительность; размер файла проверяется перед отправкой |
| Отдельная папка задачи | Пользовательские названия не используются в путях; удаление в `finally` |
| Безопасный запуск | `spawn` без shell, массив аргументов, канонические ссылки, запрет плейлистов |
| systemd | Жёсткие лимиты памяти/CPU/процессов и перезапуск после сбоя |

При сильном спаме входной guard отбрасывает избыточные события без ответа, чтобы не создавать дополнительную очередь ответов. Пользователь может повторить действие через несколько секунд. Это не распределённая защита от DDoS.

Контроль размера папки — периодический, поэтому кратковременное превышение между проверками возможно. Оставляйте запас места. Значение `MAX_JOB_DISK_MB` должно быть не меньше `MAX_UPLOAD_MB × 4`: для загрузки, объединения и финальной переупаковки. Старые папки `job-*`, оставшиеся после аварий, удаляются при запуске, если им больше суток. Выделяйте боту собственный `TEMP_DIR` и не храните в нём чужие данные.

Очередь и выбор формата хранятся в памяти одного процесса. После рестарта задания и сессии теряются: пользователь повторяет запрос. Нет гарантий доставки «ровно один раз» при аварии между принятием файла Telegram и завершением процесса. После неопределённого сетевого тайм-аута файл может всё же прийти. `/cancel` останавливает ожидание, загрузку, FFmpeg и по возможности исходящую отправку, но уже доставленный файл не отзывает.

Для нескольких экземпляров и долгоживущих задач следующим шагом будут Redis/BullMQ, внешние сессии, распределённые ограничения и отдельные workers. Подключать несколько независимых процессов к текущей локальной очереди нельзя. В таком масштабе нужны также мониторинг CPU/RAM/диска и реальные нагрузочные измерения с вашим набором роликов.

## 8. Основные настройки

Все значения в `.env.example` снабжены пояснениями. Размеры здесь **десятичные МБ**: `49` = `49 000 000` байт.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | обязательно | Токен BotFather |
| `ADMIN_USER_IDS` | пусто | Владельцы команды `/reload_channels` |
| `CHANNELS_FILE` | `./config/channels.json` | Файл обязательных каналов |
| `DOWNLOAD_CONCURRENCY` | 1 | Одновременно выполняемые задачи, включая отправку |
| `MAX_QUEUE_SIZE` | 20 | Число ожидающих задач |
| `USER_COOLDOWN_SECONDS` | 15 | Пауза между принятыми загрузками |
| `MAX_DURATION_SECONDS` | 1200 | Лимит длительности ролика |
| `MAX_VIDEO_HEIGHT` | 720 | Максимальная высота видео |
| `MAX_UPLOAD_MB` | 49 | Лимит готового файла |
| `MAX_JOB_DISK_MB` | 250 | Мягкий лимит временной папки задачи |
| `MIN_FREE_DISK_MB` | 512 | Минимальный остаток диска; перед стартом нужен ещё запас на задачу |
| `JOB_TIMEOUT_SECONDS` | 600 | Полная обработка после выхода из очереди |
| `PROCESS_TIMEOUT_SECONDS` | 180 | Один вызов yt-dlp / FFmpeg / ffprobe |
| `TELEGRAM_TIMEOUT_SECONDS` | 180 | Тайм-аут API и отправки файла |
| `SUBSCRIPTION_CACHE_SECONDS` | 60 | Короткий кеш для меню; скачивание требует свежей проверки |
| `SESSION_TTL_SECONDS` | 86400 | Время хранения выбранного формата |
| `TEMP_DIR` | `./data/tmp` | Выделенная временная папка |

Оставьте `TELEGRAM_API_ROOT=https://api.telegram.org`. Для облачного API конфигурация намеренно запрещает поднимать лимит выше 49 МБ. Изменение только числа в `.env` не увеличивает лимиты Telegram. Для более крупных файлов нужен отдельный локальный Telegram Bot API с настройкой, миграцией и пересмотром тайм-аутов/ресурсов; это не требуется для выбранного сценария.

## 9. Диагностика и обновления

**Проверка подписки не работает.** Убедитесь, что бот администратор всех каналов, ID верные, пользователь уже принят в приватный канал. Проверьте `npm run doctor -- --telegram`. При ошибке Telegram доступ закрывается, а не разрешается.

**403 при отправке сообщения.** Пользователь мог заблокировать бота. Процесс продолжит работать, файлы задачи будут удалены.

**401.** Токен неверен или отозван. Обновите `.env` и перезапустите.

**409 / другой polling.** Остановите второй экземпляр с тем же токеном, в том числе на ноутбуке. Не запускайте бесконечно новые процессы в попытке исправить конфликт.

**Настроен webhook.** Бот проверяет его до начала polling. Если вы действительно переводите этого бота с webhook на polling, сначала остановите старую интеграцию и выполните:

```bash
npm run setup:telegram -- --delete-webhook
```

Эта команда явно удаляет webhook и настраивает меню команд. Ранее накопленные обновления сохраняются.

**YouTube просит вход, сообщает bot check или не отдаёт форматы.** Обновите yt-dlp, проверьте Node.js 24 и компоненты EJS. Некоторые IP дата-центров блокируются YouTube. Это ограничение внешней платформы, а не проблема очереди. Персональные cookies в проект не включены. Для диагностики на своей машине можно выполнить непосредственно:

```bash
yt-dlp --ignore-config --no-js-runtimes --js-runtimes node --no-playlist --simulate 'HTTPS_ССЫЛКА_НА_ВАШ_РОЛИК'
```

На Windows при отсутствии yt-dlp в PATH используйте полный путь через `&` в PowerShell. Не публикуйте cookies и полные диагностические журналы с приватными данными.

**Файл слишком большой.** Бот оценивает размер и выбирает меньшее разрешение, но оценка YouTube бывает неточной или отсутствует. Окончательное решение — по реальному файлу. Попробуйте более короткое видео или аудио. Короткий ролик высокого битрейта тоже может превысить 49 МБ.

**Нехватка места/памяти.** Начните с `DOWNLOAD_CONCURRENCY=1`, проверьте диск и журнал systemd. Не увеличивайте очередь вместо увеличения производительности: она увеличивает только время ожидания.

**Журналы.** Записываются JSON-события и коды ошибок без токенов, пользовательских ссылок, текстов сообщений и сырого stderr. Для внешних программ stderr используется только для классификации ошибки. В режиме разработки диагностируйте конкретный ролик вручную локально.

Обновление yt-dlp на Windows:

```powershell
& 'C:\Tools\yt-dlp\yt-dlp.exe' -U
```

На Linux остановите службу, обновите пакет в virtualenv, проверьте окружение и снова запустите службу:

```bash
sudo systemctl stop telegram-media-bot
cd /opt/telegram-media-bot
sudo -u mediabot .venv/bin/python -m pip install --upgrade 'yt-dlp[default]'
sudo -u mediabot npm run doctor
sudo -u mediabot npm run smoke
sudo systemctl start telegram-media-bot
```

Зависимости Node устанавливайте через `npm ci` из приложенного `package-lock.json`. Проверять известные проблемы можно через `npm audit --omit=dev`. Не применяйте `npm audit fix --force` вслепую: он может заменить библиотеку несовместимой версией.

## 10. Что проверить перед использованием

```bash
npm run check
npm test
npm run smoke
npm run doctor -- --telegram
```

Автотесты покрывают нормализацию ссылок, некорректные настройки, выбор формата, все статусы подписки, сбои Telegram, сброс кеша при смене каналов, атомарную перезагрузку, очередь при всплеске 100 запросов, отмену, тайм-ауты, ограничение диска, очистку, основной сценарий через настоящий middleware библиотеки 2.x и потоковую отправку через её настоящий API с подменённым HTTP-транспортом.

После настройки токена проверьте вручную: неподписанного пользователя, вступление во все каналы, MP4, MP3, неверную ссылку, длинный ролик, отписку, изменение списка каналов, два пользователя одновременно, повторную ссылку и `/cancel`. При ручной проверке видео убедитесь, что есть и изображение, и звук.

Проект проверяется автоматически на Linux; реальный Windows 11 и доставка через ваш токен требуют проверки у вас. Прямой доступ к YouTube в среде подготовки проекта был отклонён сетевым прокси (`403`), поэтому успешная живая загрузка не заявляется. Установленный актуальный yt-dlp и реальный FFmpeg проверены отдельно; сетевой сценарий изолирован в платформенном адаптере.
